# 换种说法与多条证据的一次补查

首次查找仍忠实使用用户问题。未命中、缺少一个必要事实或证据冲突时，宿主模型先指出缺口，将当前问题译成可能写在记录里的词。问题有会改变检索方向的歧义时先澄清，不猜诊断。

例如要核对连接的两个要求，可以把“加密套件”和“证书更新周期”分别作为查询方向，而不是把所有词拼成一句，让每条只记了一个事实的记录都显得“不够相关”。

```json
{
  "query": "连接要遵守哪些加密和证书要求？",
  "refinement_queries": ["cipher suite", "certificate renewal"],
  "conversation_id": "<宿主签发的真实会话ID>",
  "turn_id": "<与首次查询相同的真实回合ID>"
}
```

命令行同样支持：

```powershell
python scripts/hfa_manager.py recall ./my_memory --query "连接要遵守哪些加密和证书要求？" --refine-query "cipher suite" --refine-query "certificate renewal"
```

- 最多3个方向，每个1–256字符。不含额外调用模型、下载或外部请求。
- 每个方向保留原有弱匹配过滤。各方向按排名合并（RRF，常数60），同一记录只占一条；没有修改原始记忆或索引格式。
- 默认无方向的单查询排序不变。所有方向共用当前主线、读取授权、替代链、条数和预算；不会自动放开侧分支。
- 目录默认最多2条。需要3条以上证据而目录不允许时，只能说明证据不足，请目录所有者决定配置，不能由模型自行提额。
- `--no-refinement` 禁止附带方向。开启 `max_recalls_per_turn` 后，整个合并算一次成功召回，不是每个方向各占一个回合；没有可信宿主身份时不能声称精确限流。
- 可选语义模式仅为原问题做嵌入推理；额外方向做词法检索。不降低默认语义阈值，也不接入实验性重排模型。
- `query_plan` 标出调用方提供的方向和数量；详细匹配的 `query_indices` 用0表示原问题、1–3表示方向。访问日志只记方向数量，不保存词本身。

一次工具请求可能包括原问题加3个方向。方向内部也可能做词形归一化或分句，不等于一次 SQLite 操作，不能把工具调用计数冒充内部检索成本。首次加补查的两份正文、工具外层与模型提词的开销也不能忽略。

收到结果后仍需核对正文是否回答问题。相关不是正确、完整或获准更新决定的证明；仍有缺口就说明未知并停止自动补查。此机制不保证理解任意隐含含义。

开发验证分别记录单查询、相同模型提词下的旧式拼词与分方向补查。公开题的模型编写查询方向不是盲测，工具链测试也不证明任何具体宿主会自动按规则调用。生产安装需更新代码和技能说明并重载服务；仅改源码不代表日常宿主已经升级。
