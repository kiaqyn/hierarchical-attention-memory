  • 按词项查找过去的项目决定。
  • 保护主线，延后非主线与历史材料。
  • 保存原始记录，维护索引与恢复信息。
  • 控制记忆正文预算，明确替代关系。

这些事情不能自动保证

  • 找得到所有同义改写或隐含含义。

  • 证明来源内容真实，或替你验证代码。
  • 让模型绝对遵守，或彻底抹去备份。

勾上“已核实”，系统就知道事实是真的吗？
不知道。这里是情景假设。真实代码检查输入结构、规则和来源指针，并不能认证来源或代替运行测试；保存授权也必须由可信的宿主或工作流保证，不能由模型自己声称。

            
为什么写入失败了，聊天还能继续？
记忆辅助能力出错时，不一定要阻断整个工作。但必须暴露失败，避免误以为已经保存。当前 Hook 部分写入错误只写 stderr；召回失败的部分路径会注入警告。这个实验展示的是清晰回执应有的区别，不代表真实宿主已经显示这些回执。

            
进程崩溃恢复，是否等于拔电源也安全？
不等于。恢复日志、锁和原子替换保护特定故障下的一致性；断电、文件系统持久化及外部手动修改仍有额外边界。本页不执行任何真实故障或磁盘写入。

          


          

            
THE FILE MAP
哪些是原件，哪些可以重建？

            
3D 图的“中枢—能力—日记”是讲解角色，不等于磁盘上的 L0 / L1 层级。下面才是文件职责；这些路径是说明，不会读取你的文件。

            
L0 / 主线与核心摘要
directory.md
summary.md
目录规定主线、分支和路由；核心摘要放最需要持续记住的约束。它们不是所有原始记忆的替身。历史安装可能没有根 summary.md，不能据此认定丢失数据。

            
L1 / 原始记录
chunks/*.json
每条决定的结构化原件：标题、命中词、正文、来源、项目与替代关系。索引损坏可以重建；原件丢失则不能靠索引保证完整恢复。

            
派生 / 可以重建
index/fts.sqlite
index/*.json
history/epoch_*/…
检索索引和历史汇总帮助快速查找、阅读。它们从真源生成。重建只能修复派生内容，不能让不正确的原始事实变正确。

            
恢复与运行状态
.hfa.lock
.hfa-transaction.json
history/session-state.json
history/access.jsonl
锁协调并发，事务日志支持恢复，会话账本负责去重和计数，访问记录帮助审查。它们并非都能随意删除；清理回合账本可能改变重试识别和提醒语义。

            
三个常见误解
归档 ≠ 删除
旧记录保留以便追溯，默认不再使用。墓碑与 supersedes 不能保证原文、日志、导出或备份已经清除。
来源指针 ≠ 事实证明
写了某个文件路径，只说明记录声称来自那里。文件内容、测试结果和适用条件还需要核验。

          


          

            
FROM MAINTENANCE TO RESEARCH
下一步改哪里，才有实际收益？

            
把工程维护、运行可靠性和记忆效果分开。更多模块、更多动画、更多版本号，都不能替代独立任务上的结果。

            
当前源码可见的问题
先让失败可见
部分写入故障的提示不够明显；访问日志与回合账本持续增长。先明确失败回执和保留策略。验收看“失败能否被发现、重复写是否避免、长期资源是否有界”。

            
工程改进 / 需量测
模块与进程内 API
按职责拆分可以改善维护；常驻 API 可能减少进程启动开销。必须保留锁、恢复和并发隔离，量测延迟后再决定。文件拆开不等于模型更聪明。

            
候选研究 / 尚未实现
经验什么时候适用？
例如“Windows 上的终端修复经验”，换到 Linux、换版本后是否仍适用？可研究保存条件与验证结果、识别失效、按需复查。当前 HFA 不会自动证明这些条件，这也还不是已确认的独创方法。

            
用什么证明改进有效？
  • 同一模型、相近上下文预算，对比无记忆、固定摘要与成熟工具。
  • 既测召回，也测实际任务成功、过期经验误用和跨项目污染。
  • 保留不参与调试的独立题目，同时记录时间与模型调用成本。
  • 测试通过只覆盖测过的输入；一次真实 canary 只证明那次链路。

            
这个页面能替我测出 HFA 比竞品强吗？
不能。所有实验使用少量固定合成记录，没有执行真实后端或竞品。它帮助理解问题和设计反例，成绩要由独立、可复现的评测产生。

          


          

            
PLAIN LANGUAGE FIRST
把术语翻译成人话。

            
Hook / MCP：一个自动触发，一个主动调用
Hook 是宿主在特定时机运行的脚本，比如回答前召回。MCP 提供模型可以调用的工具。安装了工具，不代表每轮自动调用；脚本能手工运行，也不代表宿主实际启动了它。

            
词法检索 / 语义检索：看词，还是看意思？
词法检索依赖词项与文本匹配；BM25 是其中一种排序方法。语义检索通常用向量寻找含义接近的表达，也会误召回、需要额外资源。HFA 当前没有向量后端；本页只做更简单的词项示意。

            
Token 预算：给记忆正文规定篇幅
token 是模型处理文本的单位，不等于汉字数。计数方法可能是 tokenizer，也可能是保守上界；还要区分记忆正文和整个宿主请求。这里的“最多几段”只帮助看取舍。

            
Supersedes：新决定明确替代哪一条旧决定
它需要显式关联旧记录 ID，不能仅凭“这条更新”就把所有相似内容判错。旧记录仍保留；默认召回排除它不代表物理删除。

            
幂等 / request_id：同一次重试不要保存两份
相同事件重复提交，复用同一个 ID 和相同内容；系统识别为重复。同一个 ID 换了内容应当报冲突。换 ID 会被当成新事件。

            
事务 / 锁 / 恢复：防止读到写了一半的笔记
锁协调同时访问，事务记录把关联文件更新作为一组处理；失败后按恢复规则回到一致状态。它们保护存储过程，不负责判断记忆内容是否正确。

            
Fail-open：辅助能力失败时继续主任务
这不应该等于悄悄假装成功。理想行为是允许工作继续，同时明确标记“本轮记忆未保存/不可用”，保留可重试的事件身份。
