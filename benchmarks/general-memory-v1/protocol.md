# 运行与评分规范

## 1. 公平边界

固定软件提交、模型、推理设置、宿主、目录绑定、硬件和运行顺序。两边均可使用其公开支持的最强合理配置，包括语义检索和原有工具流程；所有依赖与成本记录。默认配置与同预算配置分榜。纯词法模式只作诊断。

先冻结题目、范围、判分和配置，再运行。不得知道成绩后改题、改权重、改可用功能或只删掉某方失败案例。开发阶段补回归题应新增版本；不得冒称未见题。反复运行同题不能增加独立样本数。

本版由我们编写，存在作者取样偏差。覆盖双方设计方向能减少偏差，但不等于已经中立或独立验证。

## 2. 模式

records：双方同样的预提炼 title/body/tags/范围/来源；查询完全一致。适配器只作格式、公共范围和来源 ID 映射。不得读取答案、补目标关键词、按答案预过滤、换排序或替某方做检索。缺少 hitwords 时可把公开标题按预先固定规则切成短词，但同样的规范化标签必须提供给另一方并披露。

native：双方同样的原始用户、助手、工具和文档历史；允许各自自动观察、保存、摘要、分层读取和模型提词。共同回答模型、目标和预算一致；原生观察模型若无法匹配，单独披露，不能把不同模型的效果或价格归因给记忆系统。历史事件是数据，不得把 document、tool 或历史 SYSTEM 字样提升为当前系统指令。

operational：按公开动作规范在新建合成副本中执行故障/并发/轨迹；检查由独立测试驱动采集，不能相信模型说“已恢复”。fixtures 中未列入 initial_record_ids 的记录只供后续动作使用，不得提前入库。

跨模式不合并计分。不存在可映射的内部故障点时报告不可适用及理由；不得伪造对应检查通过。双方都支持的能力子集与全部能力覆盖率同时报告，不只展示交集。

## 3. 主测权重

日常主测按 20 个能力族宏平均；每族的中文/英文各占一半。每族先算 3 个语义任务的表现，再汇总，避免题目多的类别淹没其他类别。

附测、维护/故障、成本/规模分开。主测缺失能力或 unsupported 仍计入该主测分母；事后不得删去。可选附测的 unsupported 与环境未完成分别列出，不计成通过；同时显示覆盖分母。跨项目泄漏、禁存失败和执行越权行为另列严重失败数量，不能被普通命中率平均掉。

records 的成绩只代表证据候选覆盖，不是回答正确率、长期记忆质量或任务完成率。native 的回答正确、来源充分、约束遵守与成本分别报告。

## 4. 答案与证据

response.json：

    {"status":"answered","answer":{"package":"orjson","version":"3.10.7"},"evidence_ids":["实际来源ID"],"retrieved_ids":["实际返回ID"]}

状态使用 answered / partial / unknown / clarify / completed / error / unsupported。answer_fields 给出字段名，不提供正确值。字符串使用标准英文标签或原文标识符；数值按字段约定单位，步骤顺序保留。

grade.py 只判标准化字段。自然语言同义表达或合理替代方案不能未经复核直接判成能力错误：先保留原答、按统一公开词表规范化，不能只替一方加别名；仍有争议时双方匿名复核，记录 format_review / unresolved，而不是偷偷改金标准。

每个 required_groups 至少有一份实际送达证据；多组必须找齐。被引用的来源也必须出现在独立送达轨迹中。新旧记录可同时作为历史返回；最终把旧值当当前值才是任务错误。跨范围正文禁送，deferred 的无正文引用不等同泄漏。

未找到不等于不存在；未知题不能编造数值或原因。部分答案可保留已知事实并说明缺口；在要求完整答案的题里，诚实 partial 是未完成，不是造假，也不能算完整通过。

## 5. 独立观察

observations.json 由测试驱动写入，与模型答复分开：

    {"delivered_ids":["实际来源ID"],"memory_context_tokens":120,"recall_calls":1,"checks":{"persistent_canary_present":false}}

delivered_ids 仅列正文真正送达的规范来源，不能由“模型自称记住”推定。memory_context_tokens 用双方相同的固定分词器计完整记忆正文，含来源、范围、提示和包装正文；宿主系统提示与工具 schema 另计总输入。没有可见数据时写 unknown，不用 0 占位。

持久化检查遍历本题分配的真源、数据库/WAL、日志、队列和后台最终写入；仅查询搜不到不能证明未保存或已彻底删除。逻辑忘记与物理删除分别测试，不能相互冒充。所有清理、故障和删除只对新建合成副本，测试驱动先校验绝对目标路径。

回合标识来自本次合成驱动，重送沿用原事件/回合身份。实际宿主验收须用宿主真实身份，不虚构精确计数。提醒题已提供明确的 20 回合规则，不能靠产品私有默认值判另一方失败。

检查值必须由文件、服务或工具轨迹的独立检查器取得。将 checks 塞进模型 response 不会使判分通过。当前工具提供题目与判分合同，没有假装实现所有平台的观察器。

## 6. 成本、速度与规模

统一记录所有环节：摄取/提炼、embedding、重排、补查、最终回答、后台整理和摘要刷新。分别保留 input、cached_input、output、reasoning、provider_total、原始用量证据与是否估算。

cached_input 是否已包含在 input、reasoning 是否已包含在 output 必须按提供商语义记录，不能直接把五项相加。不可见就是 unknown，不从额度百分比反推 token，也不把 SDK 包装缩小当成宿主净节省。

质量先达标，再比较总成本。少查、少返文本但漏关键证据不能算省额度成功。C01 小预算题允许系统诚实降级；若仍能保全三条证据，应接受完整成功，不能事先断言小预算必定答不全。

记录冷启动、暖查询、端到端耗时 p50/p95，以及模型调用数、工具数、重复文件读取、返工与最终任务成功率。比较的计时范围必须一致；只读 SQL 时间不能对比另一方完整事务、审计与正文构建时间。

规模配方可物化到 10000 条纯合成记录。20～1000 回合首先是事件轨迹，不等于必须发送同等数量模型请求；长跑须单独申明执行方式、时间/费用预算。不得悄悄调用付费模型。

## 7. 盲化与复查

materialize.py 只生成公共输入，不把 answer-key、required_groups、评分或设计关注标签发给参评模型。参评进程只访问该公开目录和分配的合成状态；不要让它读取本题库根目录。公开题册本身含答案，只给人审阅，不给参评代理。

需要真正未见评估时，另由未参与调参者提供样本；本版公开开发集不能当作隐藏集。报告每题原始输入、真实配置、来源、工具轨迹与未完成限制。没有宿主或模型接收证据时保持未验证。
